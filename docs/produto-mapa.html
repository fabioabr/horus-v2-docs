Última atualização: 03/11/2026 (a D-145: a segurança dos dados por pessoa inteira na v2.1).

É o mapa para iniciar o desenvolvimento de forma estruturada (D-134). Para cada objetivo do produto, mostra as funcionalidades que o cumprem, a entrega em que cada uma sai e onde está a definição. Ele não decide nada novo: resume e aponta para o backlog estratégico. Se houver divergência, vale o backlog.

Legenda: ✅ decidido pelo dono · 🆕 proposto pelo PO, aguardando o dono · 🔎 leitura do PO, a confirmar. A v2.0 é a primeira entrega do Horus v2, e a v2.1, a segunda (D-135). A v1.xx é o Horus de hoje, ponto de partida e fonte de reaproveitamento (D-134). Macro funcionalidade (mf) é cada peça do mapa das mfs, citada como MF-nnn:Nome.

7. Como manter

  • O mapa resume e aponta. Quando uma decisão mudar, o backlog muda primeiro, e este mapa o acompanha.
  • Funcionalidade nova entra numa linha da seção 3, com o objetivo, a mf, a entrega e a decisão que a sustenta.
  • Os objetivos (O1 a O8) estão confirmados (D-136). Mudar um objetivo pede uma decisão nova no backlog.
